- [x] 상태: complete
- 사용자 개입: [n]
- 목표: 별도 Codex 세션이 기존 `run_cdp` Chrome에 attach하고 Browser/target을 읽은 뒤 disconnect만 한다.
- 허용 범위: 동일 WSL runtime의 기존 endpoint와 attach 검증 세션.
- 변경 금지 범위: `run_cdp` 재실행, Chrome 종료, 프로필 교체, UI 자동화.
- 구현 계약: verifier는 `/json/version` 확인 후 실제 CDP client로 connect/disconnect한다.
- 사용자 시작 동작: 별도 Codex 세션의 attach-only probe.
- 선행 상태·context 변형: endpoint 준비 상태, target 0개/1개 이상, 기존 Chrome PID 유지.
- production 경로: existing Chrome → CDP endpoint → verifier attach → Browser/target readback → disconnect.
- 외부·다중 출처 로그 계약: endpoint, Browser version, target count/URL metadata, PID before/after.
- 비교·선택 판정 로그: attach success/failure와 first failed boundary.
- 진단 개인정보 경계: target URL의 개인 query/cookie/payload는 마스킹한다.
- 성공 피드백: 별도 세션에서 attach 성공, target readback, Chrome PID/endpoint unchanged.
- 실패 피드백과 최초 실패 경계: endpoint absent, connect refused, target read failure, unauthorized relaunch 시도를 구분한다.
- 변경 금지 인접 흐름: 사용자 프로필, 사이트 로그인, 재생·다운로드 workflow.
- 테스트 계약: 다른 세션의 실제 attach 결과를 lower-layer curl 결과와 분리해 기록한다.
- 권위 있는 consumer: verifier가 CDP로 읽은 Browser/target 상태.
- 완료 조건: attach-only 세션이 Chrome을 종료하지 않고 readback을 남긴다.
- 완료 증거: 별도 agent `01a10ee8-96a4-7bd2-826b-8a905aab213e`의 inline WebSocket handshake 101, `Browser.getVersion` 성공, `Target.getTargets` 15개, PID `779205` 유지, endpoint HTTP 200 유지.
